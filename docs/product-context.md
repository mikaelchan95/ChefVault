# ChefVault — Product Context

## Why ChefVault Exists

Professional kitchens have no purpose-built digital tool for recipe management. Recipes live in notebooks, Google Docs, photos, and sticky notes. When a chef needs to scale a recipe for 50 covers, they do mental math. When prepping for service, they manually aggregate ingredients across multiple recipes. ChefVault eliminates this friction.

## Problems Solved

| Problem                                | Solution                                    |
| -------------------------------------- | ------------------------------------------- |
| Recipes scattered across formats       | Centralized, structured recipe database     |
| Manual scaling is error-prone          | Automatic proportional ingredient scaling   |
| No food cost visibility                | Per-ingredient costing with recipe roll-ups |
| Prep requires manual aggregation       | One-tap prep list generation                |
| No organizational structure            | Collections with many-to-many membership    |

## User Experience Goals

1. **Speed** — Sub-second navigation. No loading screens. Kitchen-proof.
2. **Clarity** — Data-dense but scannable. Professional, not tutorial-ish.
3. **Structured data** — Recipes are structured documents, not free-form text.
4. **Minimal taps** — Every interaction earns its place. No unnecessary modals.
5. **Inline editing** — Edit in place over modal workflows wherever possible.

## Design Language

- Dark theme (#121212 background, #FF7A00 primary orange)
- Inter font family
- Material Design icons
- Rounded cards with subtle borders
- Professional, utilitarian aesthetic — a kitchen tool, not a cooking guide
